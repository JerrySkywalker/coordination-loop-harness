# 设计理由

## 为什么是仓库支架，而不是 Agent Server？

ChatGPT 网页端与 Codex CLI 工作流的困难不在消息传输，而在耐久范围、授权与证据。
仓库天然提供 Review、不可变 Commit 身份、分支保护和可读历史，不需要再引入一个高权限服务。

## 为什么采用协作式 Lease？

本项目面向一个 Owner 管理多个可信 Codex 会话的场景。共享原子文件系统足以防止意外重叠，
同时保持可检查性。它不声称提供分布式共识，也不防御恶意 Writer。

## 为什么采用 MIT？

核心贡献是一套小型协议、Schema 和参考工具。宽松许可证便于团队适配自己的仓库、CI 与 Agent 产品。

## 为什么运行时不自动控制 ChatGPT 或 Codex？

自动操作网页会话或启动编码 Agent 需要凭据、浏览器状态和生命周期所有权，会显著扩大威胁面，
并把协调仓库变成高权限编排器。本模板刻意止步于生成可审阅 Prompt Artifact。

## 为什么要密封 Run Bundle？

文件名清单无法证明内容与完整性。Seal 记录确定性的 SHA-256 条目及 Companion 绑定，
再与重新枚举结果比较，从而在不复制本地原始证据的前提下暴露缺失、额外、变更或未哈希对象。

## 为什么区分 Audit 的声明属性与已验证属性？

Audit 文件可以如实记录进程自称只读或独立启动，但同一进程不能机械证明自己的隔离性。
因此 v0.2 将 asserted 与外部 verified 字段分开保存。
