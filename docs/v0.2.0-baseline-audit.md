## Existing implementation

The v0.1.0 prototype provides:

- strict JSON Schemas for requests, plans, goals, manifests, status, outcomes,
  decisions, audits, and repository-set leases;
- basic durable run materialization;
- cooperative local repository-set lease overlap checks;
- optimistic generation checks for lease replacement and release;
- an attach prompt renderer that does not launch another process;
- narrow durable-artifact secret-pattern checks;
- repository JSON Schema validation;
- a Python CLI with PowerShell wrappers;
- Windows and Ubuntu CI for Python 3.11 and 3.12.

## Material gaps

- Run manifests enumerate files but do not seal their content hashes.
- Markdown/JSON companions are not cryptographically bound.
- A decision path string is accepted without validating the decision content,
  authorization, sequence, lease generation, or Markdown binding.
- Repository identity and exact-ref verification are not implemented.
- Status has no transition engine, preserved history, or privileged-transition
  authorization.
- There is no normalized blocker model.
- Audits have a schema but no record/verify lifecycle.
- Bound Goal export and local coordinator manifests are absent.
- Derived-repository bootstrap and template sync planning are absent.
- CI does not include macOS or the complete supported-version contract.
- There is no GitHub bootstrap workflow or synthetic end-to-end parity fixture.
- Ruff is not clean at the baseline.

These gaps define the implementation and acceptance scope for v0.2.0.
